# 坊洁巡维 · 公厕开放时段核算

把巡维停水和故障记录裁剪到公厕承诺开放的时间窗，按设施分钟出具可复核的月报。

## 使用场景

模拟客户为坊洁市政环卫站。桥西、站前、河畔和北坊四个片区共管理 4 座公厕，由 2 组巡维人员轮班。早晚班在纸质交接表记录开闭门和恢复时间，分析员在 Excel 拼接跨夜记录，片区负责人从工作群收图签发月报。原流程容易把跨夜记录切错日期、重复扣减同一设施的多条报障，也容易把整修期间没有开放承诺的设施标成 0% 可用。

上游为开放规则台账、巡维交接记录和门磁开关导出。工作台负责冻结、裁剪、分钟加权、门磁对账、审阅和发布。下游为街道环卫月报和巡维排班会，按快照编号及 SHA-256 对账。

| 角色 | 演示账号 | 页面和典型操作 |
| --- | --- | --- |
| 分析员 `analyst` | `analyst` | 读日历、停用及全部版本，登记设施、窗口及停用，导入门磁开关 CSV，建版并执行，补录后冻结修订版，下载已核算版本 |
| 业务复核 `reviewer` | `reviewer` | 读日历、停用及全部版本，在月报审阅中复核重合与各自独有的停用分钟，发布已核算版本，下载月报 |
| 观察员 `viewer` | `viewer` | 读日历和停用，通过月报审阅查看及导出已发布版本 |

演示账号统一密码 `Fangjie2026!`。会话使用有效期 8 小时的 JWT，每次 API 请求以数据库里的角色判断权限。登记、门磁导入、建版、提交、核算完成或失败、发布及修订写入审计表。

## 十一月工作剧本

1. **08:30** 分析员林清从 `开放规则_2026-11.xlsx` 核对桥西全天、站前每天 20:00 至次日 02:00、河畔每天 07:00 至 19:00，北坊整修整月无计划。站前另有 21:30 至 23:00 的重叠窗口。
2. **08:45** 打开「停用核对」，对照 `巡维交班_2026-11.csv` 的 8 条停用登记，并导入门磁导出 `巡维门磁_2026-11.csv`。11 月 12 日站前 23:30 停水，与 11 月 13 日 00:15–03:10 的故障交叠，并延伸到闭馆后。门磁 `MC-1108` 只有开门端、`MC-1109` 只有关门端，页面标为「单端待核」。
3. **09:00** 在「窗口核算」新建 `十一月巡检·首次冻结`，月份填 `2026-11`，缺证据的当天选「先出已判明分钟」。版本保存了当时的开放规则、会与月份相交的停用记录及门磁记录。
4. **09:30** 执行首次冻结：承诺开放 75,600 分钟，其中已判明开放 74,875 分钟（待核 725 分钟），有效停用 350 分钟，实际可用 74,525 分钟，全辖区 99.53%。停用明细里重合 169 分钟、仅门磁 65 分钟、仅登记 116 分钟。桥西 11 月 20 日、站前 11 月 24 日各有一段待核，北坊无开放分母。
5. **09:45** 补录河畔的 `WX-1109`，开始 `2026-11-12 09:00`，恢复 `09:40`，原因为设备故障，备注 `入口指示灯故障，现场更换`。该时段与门磁 `MC-1105` 完全重合。在首次冻结上点「补录后重算修订版」得到 V2，只重算河畔 11 月 12 日这一天，其余 119 个设施日照用原结果；有效停用仍是 350 分钟，但重合变成 209 分钟、仅门磁降到 25 分钟，说明重复登记的停用不会多扣一分钟。
6. **10:15** 业务复核陈亭查看「月报审阅」。选择 11 月 12 日，确认河畔的登记与门磁重合段只计一次；切到 11 月 20 日，确认桥西 10:15 之后标为待核而不当作开放。若建版时改选「整日暂缓」，桥西与站前那两天整天不计入分母（暂缓 1,800 分钟），其余日子照常出数。核对北坊的 `无开放分母` 后发布 V2。
7. **10:30** 晚到门磁补齐 `MC-1108` 的关门时间和 `MC-1109` 的开门时间后，再点「补录后重算修订版」得到 V3：仅重算桥西 11 月 20 日、站前 11 月 24 日两个设施日，沿用 118 个设施日。待核归零、已判明开放回到 75,600 分钟，有效停用 400 分钟，实际可用 75,200 分钟，全辖区 99.47%。观察员仍可按 `V1` 找到首次冻结并导出 `开放时段-2026-11-V1.csv`；修订版各自独立编号，核对 `TOTAL` 行和 SHA-256，北坊的可用率单元格留空。

两个上游文件名用于说明值班剧本，演示样本由 `backend/scripts/seed_demo.py` 写入；本版在工作台逐条登记停用并导入门磁 CSV。

## 指标口径

- 时间按北京时间解析，最小单位为分钟。月份、周规则展开段、停用及门磁开关都是左闭右开区间 `[start, end)`。周规则以开门日归属，最多延续 24 小时。每月从上月最后一天开始展开规则，保留跨入当月午夜后的一段，再裁剪到当月。所有分钟都先裁剪到当月、再裁剪到承诺开放窗口，闭馆时段不计入任何分子分母。
- 每座设施分别合并计划窗口为 `P`、合并全部停用登记为 `R`、合并成对门磁记录的关门段为 `D`（都取并集，重叠记录不会重复计算）。门磁与登记各自只提供「停用证据」，两者相交才是同一段停用的双重印证。
- 缺一端的门磁记录既不证明开放也不证明停用。它只把当天从该端时间到最近一条门磁事件之间的时段标为待核，不能当作开放或停用的凭据；整月没有门磁记录的设施回退到停用登记口径核算，并在界面标注 `无门磁记录`，不会凭空推断门磁状态。
- **缺证据当天的两种口径**（建版时选择）：`partial` 先出已判明分钟，把待核时段单列并从分母中剔除；`defer` 当天只要有待核时段，就把该公厕这一天整天暂缓，不进入分母，其他公厕照常出数。两种口径下待核分钟都不会被当成开放或停用。
- 已判明开放 `P*` 为承诺开放减去待核时段。有效停用 `|P* ∩ (R ∪ D)|`，实际可用 `|P*| − 有效停用`。停用明细拆为三块：双方重合 `|P* ∩ R ∩ D|`、仅门磁 `|P* ∩ D − R|`、仅登记 `|P* ∩ R − D|`，三块相加恰等于有效停用。
- 单设施可用率为 `100 × 实际可用分钟 ÷ 已判明开放分钟`。辖区先分别汇总分钟，再做同样的除法。分母为零时，API 为 `null`，界面标注 `无开放分母`，CSV 留空。可用率保留两位小数，按四舍五入显示。
- 快照以 PostgreSQL 的同一读视图采集输入并计算 SHA-256。后台以 `facility-minute-v2` 从冻结数据生成结果，CSV 带版本号、修订次数、公式版本、证据口径和输入摘要。Redis 唤醒 worker，PostgreSQL 持久化排队及结果。任务异常回滚后仍可被后台接手，业务计算失败可从页面重试原快照。
- 修订版冻结时比较新旧输入，算出受影响的设施日（停用或门磁起止变化所覆盖的日期、规则或证据口径变化的整天）。核算只重算这些设施日，其余设施日的分钟原样沿用，所以晚到记录补齐后重跑不会重复计数，也只改动受影响的时段。已发布版本不被改写：修订版是新的快照编号，原编号仍能查到发布时的对账结论。

## 门磁 CSV 导入

`POST /api/door-records/import`（分析员，`multipart/form-data`，字段 `file`）接受 UTF-8 CSV，列名可为中文或英文：

| 列 | 必填 | 说明 |
| --- | --- | --- |
| `记录编号` / `code` | 是 | 全局唯一；同编号再次导入视为补全或更正 |
| `设施编号` / `facility_code` | 是 | 须已登记 |
| `关门时间` / `closed_at` | 二选一 | 北京时间，精确到分钟，可留空表示缺一端 |
| `开门时间` / `reopened_at` | 二选一 | 北京时间，精确到分钟，可留空表示缺一端 |
| `备注` / `note` | 否 | 现场说明 |

同一文件按内容 SHA-256 去重，重复上传返回 409 且不写入。缺一端的行会保留并标记待核，而不是丢弃或当作已开关。

## 启动与开发

在独立使用项目时，从项目根目录启动。批次验收需从批次根目录调用共享脚本。

```bash
cp .env.example .env
docker compose up --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

| 入口 | 地址 |
| --- | --- |
| 工作台 | `http://127.0.0.1:18280/` |
| API 和健康检查 | `http://127.0.0.1:19280/docs`、`/health` |
| PostgreSQL | `127.0.0.1:17780` |

前端原生 HTML/CSS/JavaScript 通过 Nginx 提供，`/api/` 代理至 FastAPI。后端和 worker 共用 Python 3.11 镜像。PostgreSQL 16、Redis 7 与 CSV 导出各有其命名卷。修改 `frontend/src` 或 `backend/src` 后，以 `docker compose up -d --build <service>` 重建相关服务。独立开发需停栈时运行 `docker compose down`；本地样本确认可丢弃时，可追加 `-v` 清除数据卷。

| 环境变量 | 用途 |
| --- | --- |
| `COMPOSE_PROJECT_NAME` | Compose 名称，默认 `restroom-availability` |
| `FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` | 本机回环端口，默认 `18280`、`19280`、`17780` |
| `NETWORK_SUBNET` | 默认 `10.221.211.0/24` |
| `POSTGRES_DB`、`POSTGRES_USER`、`POSTGRES_PASSWORD` | 数据库初始化和连接参数 |
| `JWT_SECRET` | 签名密钥，独立部署时使用自有随机值 |
| `SEED_DEMO` | 启动时登记演示数据，使用自然键忽略已有行，默认 `true` |

`backend/migrations` 定义持久化表，`backend/src/services/availability.py` 计算区间、门磁对账与增量重算，`backend/src/services/door_csv.py` 解析门磁导入，`backend/src/worker.py` 消费待核算版本。`frontend/src/pages` 包含四个业务模块，共用时间轨道、状态标签和编辑对话框。共享枚举 `Role`、`Reason`、`Status`、`EvidencePolicy` 见 `backend/src/constants/business.py`、`frontend/src/constants/business.js` 和 `backend/migrations/001_initial.sql`。权限在身份依赖、菜单及页面按钮中使用，原因在停用表单及列表中使用，证据状态在门磁列表、月报对账条和单日轨道中使用。

## 使用边界与许可

适用于周重复开放规则、已有恢复时间的停用事件和成对或单端的门磁开关记录。临时节假日规则、批量停用导入、已发布版本撤回及跨月未闭合门磁记录的自动补全未纳入此版；单端记录只作为待核证据，不会自行推断闭门或开门。月度快照按采集时的开放规则与门磁记录回算，录入人员应先核对规则是否适用于所选月份。此仓内容供本批次模拟和验收使用，未另授开源许可。
